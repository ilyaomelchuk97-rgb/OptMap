# OptMap — оптимизатор маршрута по точкам

Собственный движок построения автомобильных маршрутов и оптимизации порядка
объезда точек (задача коммивояжёра): **честный километраж** по реальной
геометрии дорог и **честное время** с учётом ограничений скорости
(`maxspeed` из OpenStreetMap) и загрузки дорог («пробок») по времени суток.

Состоит из:

- **движка**: граф дорог → привязка точки к дороге (снап до метров) → поиск
  пути (A*) → матрица времени/дистанций → оптимизатор порядка точек;
- **REST API** для интеграции с вашим сайтом;
- **демо-страницы с картой** (Leaflet): кликаете точки — получаете оптимальный
  маршрут с километражем, временем и средней скоростью по каждому участку.

---

## Быстрый старт

```bash
npm install
npm start            # http://localhost:8787
```

Без загруженного графа приложение работает на **демо-данных** (синтетическая
сеть в координатах Минска) — удобно посмотреть логику. Для боевого режима
загрузите реальные дороги OSM (см. ниже).

### Загрузка реальных дорог (Россия/СНГ и весь мир)

```bash
# вариант 1: файл с download.geofabrik.de (рекомендуется для города/области)
wget https://download.geofabrik.de/europe/belarus/minsk-city-latest.osm.pbf   # пример
npm run ingest -- --pbf minsk-city-latest.osm.pbf --out data/graph.json.gz

# вариант 2: скачать дороги по прямоугольнику из Overpass API (нужен интернет)
npm run ingest -- --overpass "53.80,27.40,54.00,27.70" --out data/graph.json.gz

# вариант 3: XML-выгрузка (.osm / .osm.gz)
npm run ingest -- --xml minsk.osm --out data/graph.json.gz
```

Готово — перезапустите `npm start`. Все расчёты теперь идут по реальной сети.

### Docker

```bash
docker compose up --build     # http://localhost:8787, граф монтируется из ./data
```

## Как считается «честный» километраж и время

| Что | Как |
|---|---|
| **Километраж** | Сумма длин участков по точной геометрии дорог OSM (гаверсинус по полилиниям). Точка прикрепляется к дороге проецированием на ближайшее ребро — без «скачков» до перекрёстка. |
| **Ограничения скорости** | Тег `maxspeed` из OSM; если его нет — типовые значения для городов СНГ (второстепенная 50–60, магистральная 60–70, шоссе 90–110 и т.д.). |
| **Время** | `длина ÷ (maxspeed × коэффициент загрузки)`, посекционно по каждому ребру маршрута. |
| **Пробки** | Модель по времени суток: часы пик (8–9, 17–18) замедляют магистральные улицы до ~2×, местные — сильнее; ночью — свободный поток. Будни и выходные различаются. Профиль настраивается своим JSON (`TRAFFIC_PROFILE`), интерфейс допускает подключение внешних данных о трафике. |
| **Односторонние** | Учитываются (в OSM — тег `oneway`, развязки, круговые движения). Матрица времени асимметрична — оптимизатор это использует. |
| **Оптимизация порядка** | Точный алгоритм Хелда-Карпа до 12 точек (гарантированно оптимальный порядок), дальше — эвристика мультистарт «ближайший сосед» + 2-opt + Or-opt (GRASP) до 50 точек. |

Открытые вопросы, которые стоит учитывать в продакшене: поворотные
запреты/развязки (сейчас не моделируются), реальные live-пробки (сейчас —
модель по времени суток; интерфейс `TrafficModel` готов к подключению фида),
качество `maxspeed` в OSM зависит от региона.

## REST API

### `POST /api/optimize` — главный метод

```bash
curl -X POST http://localhost:8787/api/optimize \
  -H "Content-Type: application/json" \
  -d '{
    "points": [
      {"lat": 53.9045, "lon": 27.5615, "name": "Склад"},
      {"lat": 53.9300, "lon": 27.6000, "name": "Клиент 1"},
      {"lat": 53.8850, "lon": 27.5200, "name": "Клиент 2"},
      {"lat": 53.9200, "lon": 27.5000, "name": "Клиент 3"}
    ],
    "options": {
      "roundTrip": true,      // замкнутый маршрут (вернуться в старт)
      "endLocked": false,     // при roundTrip=false: финиш строго в последней точке
      "mode": "time",         // time = быстрее | distance = короче
      "traffic": true,        // учитывать загрузку дорог
      "departHour": 9,        // час выезда 0–23; null = сейчас
      "returnGeometry": true  // вернуть геометрию участков
    }
  }'
```

Ответ:

```jsonc
{
  "order": [0, 2, 3, 1],            // оптимальный порядок обхода (индексы points)
  "legs": [                          // участки в оптимальном порядке
    {
      "from": 0, "to": 2,
      "fromName": "Склад", "toName": "Клиент 2",
      "distanceM": 5412,             // честные метры по дорогам
      "durationS": 512,              // секунды с учётом скорости и пробок
      "avgSpeedKmh": 38.1,
      "coords": [[53.9045, 27.5615], …]  // геометрия для отрисовки
    }
  ],
  "totals": {
    "distanceM": 34100, "durationS": 3020,
    "avgSpeedKmh": 40.7,
    "directDistanceM": 24600,        // по воздушным линиям
    "detourFactor": 1.39             // коэффициент объезда
  },
  "optimizer": { "method": "точный (Хелд-Карп)", "matrixMs": 24, "totalMs": 31 },
  "warnings": []
}
```

Точка `points[0]` — старт маршрута. Максимум точек — `MAX_POINTS` (по
умолчанию 50). Ошибки: `400` — неверный запрос/точка далеко от дорог,
`422` — нет дорожной связи между точками.

### Прочие методы

| Метод | Описание |
|---|---|
| `POST /api/route` | Маршрут между двумя точками (`{from:{lat,lon}, to:{lat,lon}, options}`). Есть и GET: `/api/route?fromLat=..&fromLon=..&toLat=..&toLon=..` |
| `POST /api/matrix` | Матрица времени (`timesS`) и дистанций (`distancesM`) между всеми точками |
| `GET /api/geocode?q=` | Поиск адреса/улицы: сначала по загруженному графу, затем Nominatim (OSM), при `src=yandex`/ключе — Яндекс-геокодер. Параметры `lat`, `lon` смещают поиск к области |
| `GET /api/geocode/reverse?lat=&lon=` | Обратное геокодирование: координаты → адрес/улица |
| `GET /api/tiles/{z}/{x}/{y}` | Тайл-прокси Яндекс Карт для подложки демо (EPSG:3395) |
| `GET /api/health` | Состояние: источник данных, размер графа, bbox, профиль пробок, наличие ключей Яндекса |
| `GET /api/mapdata` | Геометрия сети для отрисовки демо-карты (только для небольших графов) |

## Встраивание в сайт

**Вариант 1 — свой бэкенд вызывает API** (рекомендуется): считаете маршрут на
сервере и рисуете на своей карте (Google/Yandex/Leaflet) по `legs[].coords`,
километраж и время берёте из `totals`/`legs`.

**Вариант 2 — готовая страница-виджет** (iframe):

```html
<iframe
  src="http://ваш-сервер:8787/?embed=1
       &pts=53.9045,27.5615;53.93,27.60;53.885,27.52&auto=1"
  style="width:100%;height:600px;border:0"></iframe>
```

`pts` — точки через `;`, `auto=1` — сразу построить маршрут.
Демо-страница `/` — это одновременно и пример интеграции (кнопка
«Пример запроса» показывает готовый curl с текущими точками).

## Источники данных: OpenStreetMap — основа, Яндекс — опция

**Дороги, ограничения скорости, односторонние движения** — из OpenStreetMap
(это основной и рекомендуемый режим: `ROUTING_ENGINE=local` стоит по
умолчанию). **Адресный поиск** — Nominatim (геокодер OSM, без ключей) с
фолбэком на поиск по загруженному графу. Подложка карты по умолчанию —
OpenStreetMap.

Яндекс Карты — необязательные интеграции для тех, кому нужны реальные
live-пробки, адресный поиск Яндекса и подложка Яндекса. Ключи выдаются в
[Кабинете разработчика](https://developer.tech.yandex.ru/); без ключей всё
работает на OpenStreetMap (граф OSM + модель пробок).

| Переменная | Что даёт |
|---|---|
| `NOMINATIM_URL` | **Геокодер OpenStreetMap** (адресный поиск без ключей): `/api/geocode` и `/api/geocode/reverse` сначала ищут по загруженному графу, затем — Nominatim (публичный или свой инстанс) |
| `YANDEX_GEOCODER_KEY` | **Определение дорог и адресов**: поиск в строке и обратное геокодирование идут через Геокодер Яндекса (`/api/geocode`, `/api/geocode/reverse`); при недоступности — автоматический фолбэк на поиск по графу |
| `YANDEX_ROUTER_KEY` | **Реальные пробки** (опция): матрица расстояний и маршруты считаются API Маршрутизации Яндекса — честные километраж и время с текущей загрузкой дорог; при ошибке — фолбэк на OSM-движок с предупреждением |
| `YANDEX_JS_KEY` | **Карта Яндекса в примере** `/yandex.html` — официальное JS API 2.1 в браузере |
| `YANDEX_TILES` | Подложка Яндекс Карты в основном демо (тайлы проксируются сервером, `off` — выключить) |

Выбор движка в запросах:

```jsonc
// POST /api/optimize
{
  "points": ["..."],
      "options": {
    "engine": "local"    // local (по умолчанию: OSM-граф + модель пробок)
                         // | auto (Яндекс при наличии ключа, иначе OSM)
                         // | yandex (только mode=time, с пробками)
  }
}
```

В ответе поле `engine: { name, trafficType, graph }` показывает, чем считался
маршрут (`local` — OSM-граф, или `yandex` с `trafficType: realtime|forecast`).
Порядок точек всегда оптимизирует OptMap (Хелд-Карп/2-opt) — в том числе
поверх яндексовой матрицы времени.

**Пример страницы с Яндекс Картой**: откройте `/yandex.html` — точки ставятся
кликом, адреса определяются геокодером Яндекса, маршрут рисуется поверх
карты Яндекса. Это готовый шаблон интеграции для вашего сайта.

> Примечание: подложка «Яндекс» в основном демо использует тайлы веб-версии
> Яндекс Карт через серверный прокси (проекция EPSG:3395). Для боевого
> использования на сайте предпочтителен официальный JS API (пример
> `/yandex.html`) — он покрывается договором с Яндексом.

## Пробки: настройка и подключение реальных данных

Встроенная модель (`server/engine/traffic.js`) — коэффициенты по часам и
классам дорог. Свой профиль:

```bash
cp config/traffic-profile.example.json config/my-profile.json
# отредактируйте коэффициенты под свой город
TRAFFIC_PROFILE=config/my-profile.json npm start
```

Для **live-данных** о трафике реализуйте в `TrafficModel` метод `factor()`
на основе внешнего источника (фид Speeds/Traffic от провайдера данных,
датчики, исторические профили TomTom/HERE/Яндекса) — остальной движок
менять не нужно: время маршрута автоматически пересчитается по вашим
коэффициентам.

## Архитектура

```
server/
├─ index.js            HTTP-сервер (Express) + статика
├─ config.js           конфигурация (.env)
├─ routes/api.js       REST API: /optimize, /route, /matrix, /geocode, /health, /mapdata, /tiles
├─ adapters/yandex.js    адаптер Яндекс Карт (геокодер, маршрутизация, матрица)
├─ adapters/nominatim.js геокодер OpenStreetMap (адресный поиск, reverse)
├─ engine/
│  ├─ graph.js         граф дорог (узлы-перекрёстки, рёбра с maxspeed и классом)
│  ├─ ingest-osm.js    загрузка OSM: .osm.pbf / .osm.xml / Overpass JSON
│  ├─ synthetic.js     генератор демо-города (для старта без данных)
│  ├─ snap.js          привязка точек к дорогам (проекция на ребро, сеточный индекс)
│  ├─ router.js        A*/Дейкстра: маршрут и матрица (односторонние, пробки)
│  └─ traffic.js       модель загрузки дорог (часы пик, классы, профиль JSON)
├─ optimizer/
│  ├─ exact.js         Хелд-Карп (оптимум до 12 точек)
│  └─ heuristic.js     мультистарт NN + 2-opt + Or-opt (до 50 точек)
public/                демо-страница (Leaflet) и пример с Яндекс Картой (/yandex.html)
scripts/ingest.js      CLI загрузки графа
test/                  unit-тесты (node --test)
```

Производительность: город ~50–200 тыс. рёбер — маршрут единичной пары
10–100 мс, оптимизация 10 точек — доли секунды. Демо-город: 500+ узлов,
считается мгновенно.
